### Root Cause

We verified directly against the running server (`curl http://localhost:3000`) that **J.A.R.V.I.S.** is the server listening on port 3000 (`<title>J.A.R.V.I.S. - Autonomous AI Voice & Memory System</title>`).

The reason your browser showed **LearnIQ** is **browser-level Service Worker / Cache hijacking** on the `http://localhost:3000` origin:
- When you previously ran LearnIQ on port 3000, your web browser registered a Progressive Web App (PWA) Service Worker for `http://localhost:3000`.
- Even after stopping LearnIQ, the browser's background Service Worker intercepts all navigation requests to `http://localhost:3000` and serves the old LearnIQ files from local browser cache before the request ever reaches the network.

---

### Fixes Applied in the Codebase

1. **Automatic Service Worker & Cache Eviction in [index.html](file:///home/g0pi/Downloads/jarvis/index.html)**:
   - Added a script in `<head>` that automatically discovers and unregisters any stale Service Workers on port 3000 and clears conflicting `CacheStorage` from previous projects.
2. **No-Cache Headers in [server.ts](file:///home/g0pi/Downloads/jarvis/server.ts)**:
   - Configured `Cache-Control: no-store, no-cache, must-revalidate` middleware so the browser always fetches fresh pages in development.

---

### How to Load J.A.R.V.I.S. Right Now

To break your browser out of LearnIQ's cached Service Worker, do one of the following:

1. **Hard Refresh**:
   - In the browser tab at `http://localhost:3000`, press **`Ctrl + Shift + R`** (or **`Ctrl + F5`**). This forces the browser to bypass the Service Worker and fetch J.A.R.V.I.S.
2. **Use 127.0.0.1**:
   - Navigate to **`http://127.0.0.1:3000`**. Browsers isolate origins, so LearnIQ's cache on `localhost` cannot touch `127.0.0.1`.
3. **Clear Site Data (Optional)**:
   - Press `F12` in the browser -> go to **Application** -> **Storage** -> click **Clear site data**.

### Updates Applied

1. **Removed the Buttons Below the Text Bar**:
   - Cleaned up [CommandInputBar.tsx](file:///home/g0pi/Downloads/jarvis/src/components/CommandInputBar.tsx) by removing the quick action/directive chips below the input. The input bar is now a clean, minimalist cybernetic command console.

2. **Fixed Unintended Reactivation When Sending Messages**:
   - **Root Cause 1 (Active Session)**: Previously, sending a message checked `if (connectionState === 'connected')`. In an active session, the state is `'listening'` or `'speaking'`, causing the app to fall back to `handleStartSession()`, which tore down the existing connection and restarted the entire live voice loop and greeting.
   - **Root Cause 2 (Disconnected Session)**: When disconnected, it was also calling `handleStartSession()`, which forcibly engaged the microphone stream and live voice mode.
   - **Root Cause 3 (Completion Reset)**: `handleAssistantSpeak` was unconditionally setting `connectionState('listening')` upon finishing speech.
   - **Resolution in [App.tsx](file:///home/g0pi/Downloads/jarvis/src/App.tsx#L709-L745)**:
     - Messages are now routed directly through the existing open WebSocket without touching connection state or restarting the session.
     - Offline/disconnected queries route through REST `/api/chat` (or demo voice) without starting the microphone or switching into live listening mode.
     - Prior state is preserved so disconnected sessions remain disconnected when speech completes.
